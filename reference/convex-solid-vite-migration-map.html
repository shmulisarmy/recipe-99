The target tree

│   ├── index.tsx         ← create client + mount provider

Smallest setup sequence

npm install convex convex-solidjs
npx convex dev

# Or run Vite from the same process after configuration:
npx convex dev --start 'vite'

Client-library caveat

convex-solidjs is a community adapter, not a client listed in the official Convex docs. It offers Solid-native providers and accessors. The official fallback is ConvexClient from convex/browser; changing between them does not change the backend folder structure.

Minimal SPA seam

import { ConvexProvider, setupConvex } from "convex-solidjs";

const convex = setupConvex(import.meta.env.VITE_CONVEX_URL);

render(
  () => (
    <ConvexProvider client={convex}>
      <App />
    </ConvexProvider>
  ),
  root!,
);

Migration rhythm

  1. Choose one persisted aggregate, such as available pantry ingredients.
  2. Model only that table and its query/mutation.
  3. Replace that feature's local store access behind its existing feature boundary.
  4. Build and verify behavior.
  5. Only then choose the next aggregate.

Primary source: Convex dev workflow. See the first lesson for the reasoning exercise.

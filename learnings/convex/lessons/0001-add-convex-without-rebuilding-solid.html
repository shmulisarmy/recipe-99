1. Keep the structure you already earned

Recipe-99 already separates features behind outside_feature_exports.ts. Convex does not replace that boundary. The new convex/ directory is a sibling of src/, not a new home for the frontend.

recipe-99/
├── convex/                 # new backend boundary
│   ├── _generated/         # generated types; commit these
│   ├── schema.ts
│   └── pantry.ts
├── src/                    # stays the Solid frontend
│   ├── index.tsx           # gains the Convex provider
│   └── features/           # existing boundaries stay intact
└── .env.local              # deployment details; local only

The official workflow says that npx convex dev configures a deployment, creates convex/, watches backend functions, and maintains convex/_generated/. It does not require a meta-framework. Read the primary source.

Specific migration advice for this repository

Do not move all of src/data.ts or src/features/planner/data.ts at once. Start with one aggregate—available pantry ingredients is a good first slice—then replace only that slice's reads and writes. Local editor drafts can remain Solid state.

3. Add one frontend seam

Because this is a client-rendered Vite app, the provider belongs at the existing root in src/index.tsx. No SolidStart server entry, route loader, or hydration layer is needed.

import { ConvexProvider, setupConvex } from "convex-solidjs";

const convex = setupConvex(import.meta.env.VITE_CONVEX_URL);

render(
  () => (
    <ConvexProvider client={convex}>
      <App />
    </ConvexProvider>
  ),
  root!,
);

convex-solidjs is a community package rather than an officially listed Convex client. Its Solid-native API is convenient, but keep that choice mentally separate from the architecture: the official ConvexClient from convex/browser can replace the adapter later without relocating the backend.

4. Use two loops—or one command

npm install convex convex-solidjs
npx convex dev           # terminal 1: backend sync + codegen
npm run dev              # terminal 2: Vite

# Optional single command after initial configuration:
npx convex dev --start 'vite'

The --start option is part of the current Convex CLI. It is convenience, not architecture. See the CLI reference.

Your first real migration move

After Convex is configured, model just the pantry data, write one query and one mutation, and connect only the available-ingredients feature. That creates a complete vertical slice while leaving planner data untouched. A schema is technically optional, but this app already has known TypeScript shapes, so defining that first table early is useful rather than speculative. Convex schema guidance.

Keep the migration map open while making the first change. It compresses the tree, ownership test, setup commands, and migration rhythm into one page.
